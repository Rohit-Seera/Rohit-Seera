## About

I'm a Computer Science (AI) undergraduate at **IIIT Bhopal**, focused on building **production-grade Generative AI systems** — not notebooks that die after a demo.

My work sits at the intersection of three things: **applied deep learning** (PyTorch models trained and evaluated end to end), **LLM systems engineering** (RAG pipelines, retrieval, orchestration, streaming APIs), and **full-stack product delivery** (FastAPI backends, React frontends, CI/CD, real deployments).

Most recently I worked as a **Generative AI Intern at PhotoGPT (TAIC LLC)**, where the work was measured in shipped output rather than experiments — 300+ production visual assets and campaigns that reached **10M+ views**. That experience shaped how I build: prompt and model choices get benchmarked, pipelines get instrumented, and quality is a measurable target, not a vibe.

Alongside that I build **Mistella**, a full-stack AI workspace unifying LLM chat, conversational memory, multimodal image understanding, and document-grounded RAG behind one interface.

## Featured Projects

<details>
<summary><b>Mistella — Full-Stack AI Workspace</b></summary>

<br>

A unified AI workspace that collapses four separate tools into one interface: LLM-powered chat with conversational memory, multimodal image understanding, document-grounded RAG, and research capabilities.

| | |
| :--- | :--- |
| **Stack** | Python · FastAPI · LangChain · LangGraph · Groq · Google Gemini · FAISS · BM25 · React/Vite · PostgreSQL/SQLite |
| **Architecture** | FastAPI backend with LangGraph orchestration; modular React/Vite frontend deployed on Vercel |
| **Performance** | Real-time Server-Sent Events (SSE) token streaming; Groq inference for low-latency responses |
| **Retrieval** | Hybrid pipeline — PDF parsing, chunking, embedding generation, FAISS dense search + BM25 sparse retrieval |
| **Surface Area** | REST APIs for chat/streaming, conversation management, image & PDF upload, document indexing/retrieval, health monitoring |
| **Delivery** | Automated Git-based CI/CD, persistent conversation threads, PostgreSQL/SQLite persistence layer |

The engineering problem here wasn't calling an LLM — it was making a stateful, multimodal, document-aware assistant behave predictably. That meant designing conversation persistence that survives restarts, a retrieval layer that combines dense and sparse signals so answers stay grounded in source documents, and a streaming transport that keeps the UI responsive while long generations complete. Groq and Gemini are integrated behind a common interface so inference can be routed by latency and modality rather than hardcoded.

</details>

<details>
<summary><b>Healthcare Data Classification — Artificial Neural Network</b></summary>

<br>

A PyTorch binary classifier predicting breast cancer diagnosis from clinical measurements.

| | |
| :--- | :--- |
| **Stack** | PyTorch · scikit-learn · Pandas · NumPy · Matplotlib · Seaborn |
| **Architecture** | 3-layer ANN — 30 → 16 → 8 → 1, ReLU hidden activations, sigmoid output |
| **Training** | Binary cross-entropy loss, SGD optimizer, 200 epochs |
| **Result** | **99.12% test accuracy** |
| **Validation** | scikit-learn classification metrics; training curves visualized with Matplotlib and Seaborn |

Built to practise the full supervised-learning loop rather than just model definition: feature scaling, a deliberately compact architecture chosen against dataset size to avoid overfitting, and evaluation that reports more than a single accuracy number. Training progress was plotted every run so loss behaviour — not just the final metric — drove architecture decisions.

</details>

<details>
<summary><b>Student Academic Success Predictor — Machine Learning</b></summary>

<br>

A logistic regression pipeline predicting student pass/fail outcomes from academic records.

| | |
| :--- | :--- |
| **Stack** | scikit-learn · imbalanced-learn (SMOTE) · Pandas · NumPy · Matplotlib |
| **Core Problem** | Class imbalance — failing students were the minority class the model most needed to catch |
| **Approach** | SMOTE oversampling combined with class-weight optimization |
| **Evaluation** | Classification report, confusion matrix, ROC curve analysis |

The interesting constraint was that accuracy is the wrong metric here — a model that predicts "pass" for everyone scores well and helps nobody. The work went into rebalancing the training distribution and then evaluating with recall-sensitive metrics, so the model is judged on the cases that actually matter.

</details>
